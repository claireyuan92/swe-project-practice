PROJECT 01 — BACKEND / SYSTEM DESIGN

Twitter Backend System · Python

Rebuild the core of a small Twitter: posting, following, and the home timeline. The point isn't the UI — it's the fan-out strategy: when a celebrity posts, how does the system survive the write amplification?

PythonFastAPI / DjangoPostgreSQLRedisFan-out
Difficulty★★★☆☆ Intermediate
Timeframe2–3 weeks
Resources5 videos + 3 docs

Milestones

  1. Data model & core APIs

    Model users, tweets, and follows; FastAPI + SQLAlchemy CRUD, JWT auth, pagination.

  2. Timeline & fan-out

    Implement both fan-out on write and fan-out on read; load-test and compare latency vs. write cost.

  3. The celebrity problem & hybrid strategy

    Route by follower-count threshold: push for regular users, pull for celebrities; cache timelines in Redis (cap 800 entries).

  4. Reliability hardening

    Outbox pattern, cursor pagination, hot-key handling; add tests and deployment notes.

Final deliverable

A runnable Twitter-clone backend + architecture diagram + a fan-out trade-off write-up. Repo folder: 01-twitter-backend/

PROJECT 02 — PERCEPTION / SIMULATION

Self-Driving Car Project

No real car needed: run a complete pipeline inside the CARLA simulator — camera frames → lane and object detection → decisions and speed control. Build intuition with pure OpenCV first, then move to deep learning and reinforcement learning.

PythonCARLAOpenCVTensorFlow / YOLOApollo
Difficulty★★★★☆ Advanced
Timeframe3–4 weeks
Resources5 videos + 5 docs

Milestones

  1. Lane detection (pure OpenCV)

    Canny edges, ROI masking, Hough lines — draw lanes on driving video in real time.

  2. CARLA basics

    Install the simulator and drive the Python API: spawn vehicles, attach cameras and sensors, replay data.

  3. Perception fusion

    Object detection (vehicles / pedestrians / cyclists) + traffic-light recognition + lane keeping, following a YOLO + UFLD approach.

  4. Planning & control

    Adaptive speed control and simple motion planning; go further with MIT's deep RL work in DeepTraffic.

Final deliverable

A self-driving demo video in CARLA + the perception pipeline code. Repo folder: 02-autonomous-driving/ · Hardware note: CARLA is GPU-hungry — without a discrete GPU, finish the pure-CPU version of milestone 1 first.

PROJECT 03 — HIGH CONCURRENCY / JAVA

E-Commerce Flash Sale System · Spring

A flash sale is a concurrency problem at heart: 100,000 people chasing 100 units. How do you avoid overselling, stay up, and stay fair? From pre-deducting stock in Redis to async ordering, every layer exists to keep pressure away from the database.

Java 21Spring Boot 3Redis / RedissonLuaKafka / RabbitMQMySQL
Difficulty★★★★☆ Advanced
Timeframe3 weeks
Resources5 videos + 3 docs

Milestones

  1. Basic store & Redis integration

    Model products, orders, and inventory; wire Redis into Spring Boot for caching and sessions.

  2. Oversell protection core

    Warm inventory into Redis, atomic Lua deductions + one-order-per-user checks, Redisson distributed locks as a backstop.

  3. Async ordering & peak shaving

    Eligibility first, confirmation later: a message queue absorbs orders, the outbox guarantees consistency, Saga handles cross-service transactions.

  4. Rate limiting, circuit breaking & load testing

    Token-bucket limiting at the gateway, Resilience4j circuit breakers, Bloom filters against cache penetration; load-test to high QPS and analyze the bottlenecks.

Final deliverable

A flash-sale system that starts with one Docker Compose command + a load-test report (QPS / oversell verification). Repo folder: 03-seckill-spring/

PROJECT 04 — NLP / ALGORITHMS

NLP Sensitive-Word Detection

The first line of defense in content moderation. A comment has to be scanned against tens of thousands of sensitive words in milliseconds — not with a regex loop, but with an Aho-Corasick automaton: one pass, many patterns. Then BERT adds semantic-level toxicity classification on top.

PythonAho-CorasickTrie / DFABERTHugging Face
Difficulty★★☆☆☆ Beginner+
Timeframe1–2 weeks
Resources3 videos + 3 docs

Milestones

  1. Wordlist & baseline

    Assemble a sensitive-word list, write a naive Trie / DFA version, and measure baseline performance.

  2. Aho-Corasick automaton

    Build the Trie + failure links for single-pass multi-pattern matching; handle variants — simplified/traditional characters, full/half width, pinyin.

  3. Turn it into a service

    Wrap it in a real-time detection API: match positions, masking/redaction, and severity tiers (block / human review / allow).

  4. Model backup (advanced)

    Fine-tune BERT for multi-label toxicity classification to catch evasive phrasing the wordlist misses; compare where each approach breaks down.

Final deliverable

A sensitive-word detection service + a performance report (wordlist size vs. latency). Repo folder: 04-nlp-sensitive-words/

PROJECT 05 — BLOCKCHAIN / WEB3

Blockchain: From Principles to Applications

First compute hashes by hand, mine a block, and tamper with a chain to watch the network reject it — once the principles are solid, write Solidity contracts, issue an ERC-20, and build a DApp you can actually interact with.

SHA-256 / PoWSolidityEthereum / EVMERC-20 / NFTPython
Difficulty★★★☆☆ Intermediate
Timeframe2–3 weeks
Resources5 videos + 3 docs

Milestones

  1. Principles: hashes, blocks & chains

    Use the interactive demo to mine and tamper hands-on; understand why hash chains and proof of work resist tampering.

  2. How Bitcoin actually works

    Ledgers, digital signatures, the double-spend problem; go further by actually mining and transferring on a regtest network.

  3. Build a chain from scratch

    Implement a minimal blockchain in Python (blocks, transactions, mining, node consensus), using the blockchain-demo source as reference.

  4. Applications: smart contracts & DApps

    Solidity basics, ERC-20 / NFT, DeFi concepts, and full-stack DApp development (work through the 16-hour course by chapter).

Final deliverable

Your own mini-blockchain + a contract deployed to a testnet. Repo folder: 05-blockchain/
